# DOCCAR.PRO — сайт автосервиса (Одинцово) + CRM

Лендинг автосервиса **DOCCAR.PRO** по фирменному стилю: тёмный фон `#101318`,
лаймовый акцент `#C6F34A`, доп. фон `#2A2F36`, текст `#E8ECEF`. Знак «D + пульс»,
адаптивная вёрстка, SEO-разметка и JSON-LD. Движок — тот же, что у lenkrad.ru:
Next.js + встроенная админка + лёгкая CRM на файловом сторе.

## Стек

- **Next.js 14** (App Router), **TypeScript**, **Tailwind CSS**, **lucide-react**
- Шрифты через `next/font`: Inter (текст), Montserrat (заголовки), Exo 2 (вордмарк)
- Без тяжёлых библиотек. Карта — OpenStreetMap embed в тёмной гамме (без ключей)

## Запуск

Нужен **Node.js 24+** — CRM хранится в SQLite через встроенный `node:sqlite`.

```bash
npm install
node scripts/gen-env.mjs   # создаст .env.local с логином/паролем админки
npm run dev                # http://localhost:3000
npm run build && npm run start
```

## Страница и конструктор разделов

Страница = **главный экран** (фикс.) → **разделы** в порядке, заданном в админке →
**финальный блок** (фикс.: «Остались вопросы?», кнопки, контакты, тёмная карта).

Разделы владелец добавляет сам (админка → Сайт → «Разделы»): выбирает тип из
каталога, заполняет, переставляет, дублирует, скрывает и удаляет. У каждого
раздела — пункт меню (пусто = нет в меню), адрес-якорь (`#anchor`) и фон
(обычный / выделенная полоса). Новый раздел создаётся скрытым.

| Тип | Что внутри |
| --- | --- |
| Услуги с фото | карточки: фото (необяз.), иконка, название, описание, стрелка → запись на эту услугу |
| Преимущества | заголовок + текст слева, короткие пункты с иконками справа |
| Фото | лента фотографий (на телефоне — прокрутка) |
| Текст с фото | заголовок, абзацы, фото слева/справа |
| Карточки | иконка или номер шага (01, 02…), заголовок, текст — «Как мы работаем» и т.п. |
| Вопросы и ответы | раскрывающийся FAQ + разметка `FAQPage` для поисковиков |
| Цены | прайс: работа, примечание, цена |
| Призыв к записи | яркий баннер с кнопкой записи |
| Отзывы | карточки отзывов (только реальные) |

Меню и футер строятся из разделов; услуги для формы записи — из разделов «Услуги».
Новый тип = тип и фабрика в `lib/content-model.ts`, поля в `lib/content-normalize.ts`,
вёрстка в `components/blocks/`, редактор в `components/admin/blocks/BlockFields.tsx`.

Фото нигде не обязательны: без фото карточки услуг становятся иконочными, главный
экран показывает фирменный фон (сетка, свечение, знак, линия пульса), пустая лента
не выводится. Сгенерированных нейросетью фото в комплекте нет — только реальные,
загруженные через админку.

Все кнопки «Записаться» открывают **окно записи** (`components/BookingDialog.tsx`,
нативный `<dialog>`): имя, телефон, услуга, авто, описание. Заявка падает в CRM
(админка → «Запросы»). Ссылка `/#booking` открывает окно сразу.

## Админка — `/admin`

Вход по логину и паролю из `.env.local` (`ADMIN_LOGIN` / `ADMIN_PASSWORD` /
`ADMIN_SECRET`). Без них действуют небезопасные значения по умолчанию
(`doccar` / `doccar-admin`) — для боевого сайта задайте свои.

**Сайт** (только владелец): конструктор разделов, главный экран, финальный блок,
контакты и **точка на карте** (координаты вставляются одной строкой из Яндекс.Карт),
**фото во всех слотах** (загрузка / «Убрать»), рабочие часы календаря, SEO.
Индикатор несохранённых изменений + предупреждение при уходе со страницы.

**CRM**: роли «Владелец» / «Приёмщик» / «Механик», запросы с сайта, календарь
записей (день/неделя, анти-дабл-букинг), уведомления, статистика, бэкап.

## Данные

| Что | Где |
| --- | --- |
| Контент сайта | `data/content.json` → `normalizeContent` (проверка, дефолты, миграция старого формата), запись атомарная |
| CRM (сотрудники, заявки, записи) | `data/crm.db` — SQLite (WAL, внешние ключи), схема версионируется `PRAGMA user_version` |
| Загруженные фото | `data/uploads/` — отдаются через `/api/media/<id>` |

Каталог `data/` в `.gitignore` и монтируется томом в Docker — переживает деплой.

**CRM на SQLite.** Слой данных — `lib/db.ts` (подключение, миграции, транзакции,
снимок) и репозитории `lib/crm.ts` (бизнес-правила: последний админ, пересечения
записей у механика, связь запись ↔ заявка). Роуты — тонкая HTTP-обвязка.
Новая версия схемы = новый SQL в `MIGRATIONS` (`lib/db.ts`), применяется сама при
старте. Старый `data/crm.json` при первом запуске импортируется один раз
(висячие ссылки обнуляются) и переименовывается в `crm.json.imported`.
Откат на версию без SQLite: вернуть `crm.json.imported` → `crm.json`.
Фото, которые больше не используются в контенте (обход всего дерева контента, а
не списка полей), удаляются при сохранении; свежие загрузки младше часа не трогаются. **Бэкап** (админка → «Бэкап») —
ZIP с `content.json`, снимком базы `crm.db` (`VACUUM INTO` — консистентный, без
WAL) и всеми загруженными фото. Восстановление проверяет базу из архива
(целостность, таблицы, версия схемы), сохраняет текущую как
`crm.db.before-restore-*` и заменяет её; старые архивы с `crm.json` тоже
принимаются (импорт).

Загрузка принимает JPG/PNG/WEBP/GIF до 6 МБ; тип определяется по содержимому
файла. URL картинок в контенте — только встроенные `/images/*` или `/api/media/*`.

## Структура

```text
app/
  layout.tsx, page.tsx      # метаданные, шрифты; главный экран → разделы → финал (force-dynamic)
  api/lead                  # приём заявки → CRM
  api/media/[id]            # отдача загруженных фото
  api/admin/*               # контент, загрузка фото, CRM, бэкап
  admin/                    # вход + панель (route-group (panel) с гардом)
components/                 # Header, Hero, Contacts, Footer, MobileCTA, BookingDialog,
                            # ContactForm, Logo, JsonLd
  blocks/                   # разделы: по компоненту на тип + BlockView (рендер по типу)
  admin/                    # редактор сайта (fields.tsx — общие поля), CRM-экраны
  admin/blocks/             # конструктор разделов: BlocksEditor + BlockFields
lib/
  content-model.ts          # типы разделов, каталог типов, фабрики, DEFAULT_CONTENT (можно в клиенте)
  content-normalize.ts      # единая проверка/миграция контента + список используемых фото
  content.ts                # чтение/запись data/content.json (сервер)
  media-url.ts, media.ts    # URL загрузок (чистое) / сигнатуры, уборка (сервер)
  icons.tsx                 # реестр иконок (lucide + свои: монитор-пульс, ключ+отвёртка)
  db.ts                     # SQLite: подключение, миграции, транзакции, снимок/восстановление
  crm.ts, crm-types.ts      # репозитории CRM + типы (типы — можно в клиенте)
  auth.ts, zip.ts           # сессии, ZIP для бэкапа
config/site.ts              # ссылки на карты из координат, якорь окна записи
public/                     # favicon.svg, icon-*.png, apple-touch-icon.png, og-image.png
```

Тема: цвета — токены в `tailwind.config.ts`. Акцент — CSS-переменная: на тёмном
сайте это лайм, в светлой админке — тёмно-оливковый (`.theme-dark` / `.theme-light`
в `app/globals.css`), чтобы текст акцентом читался на белом.

## Деплой (прод)

Живёт на том же сервере, что lenkrad.ru: **135.106.175.41** (`ssh -i ~/.ssh/hvpn_deploy root@…`),
каталог `/opt/doccar`, контейнер `doccar-app`. Своего Caddy нет — TLS и порты 80/443
держит `lenkrad-caddy` (проект `/opt/lenkrad`); блок `doccar.pro` / `www.doccar.pro`
лежит в Caddyfile Lenkrad (репо wastedovi4/lenkrad) и проксирует на `doccar-app:3000`
по общей сети `lenkrad_web`. DNS — reg.ru (`ns1/ns2.hosting.reg.ru`).

> **Имя сервиса в compose — `doccar`, не `app`.** Имя сервиса = DNS-алиас в общей
> сети; одинаковый алиас `app` раскидал бы трафик lenkrad.ru на оба контейнера.

Порядок выкладки:

1. Сейф-копия `data/` и `.env` на сервере.
2. Архив исходников без `node_modules`, `.next`, `.git`, `data`, `.env*` → `/opt/doccar`.
3. `cd /opt/doccar && docker compose build && docker compose up -d`.
4. Проверка: `docker exec lenkrad-caddy nslookup app` — ровно один IP (lenkrad-app);
   https://doccar.pro и https://lenkrad.ru отдают каждый свой сайт.

Правка Caddyfile Lenkrad: файл смонтирован одиночным bind-mount — писать на месте
(`cat new > Caddyfile`, inode сохраняется), проверять `caddy validate`, применять
`caddy reload`. Если файл пересоздан (scp/tar) — нужен `docker restart lenkrad-caddy`.
